## 4. データの流れ

### 会話
1. ユーザーが送信。
2. ユーザーメッセージを履歴へ追加し、暗号化してローカル保存。
3. 質問文を使い、承認済み長期記憶から関連度の高い最大5件を選ぶ。
4. 選択した記憶と直近12件の会話をプロンプトに組み立てる。
5. WebLLMのQwen3-4Bで推論。
6. AI応答を履歴に追加し、暗号化保存・画面再描画。
7. ユーザー発言からルールベースで記憶候補を抽出。候補は承認待ち。

### 記憶候補
- `generateMemoryCandidates()` がユーザー発言を判定。
- 候補は `data.candidates` に追加される。
- 承認操作で `data.memories` に移動する。
- 承認済みの `data.memories` だけをAIプロンプトへ渡す。

### ローカル暗号化
- `deriveKey()` がパスワードとsaltからCryptoKeyを導出。
- `encryptData()` がJSONデータをAES-GCMで暗号化。
- `saveLocal()` が `ALVIS_ENCRYPTED_V1` へ保存。
- ロック時はAIモデルをunloadし、CryptoKeyとメモリ上のデータを破棄する。

### クラウド同期
- `api()` がBearerトークンを付けてWorkerへ通信。
- `saveCloudCore()` が暗号化レコードとexpectedRevisionを送信。
- 競合時は自動保存を停止する設計。
- クラウド復元は復号後、ユーザー確認を経てローカルデータを置換する。

- 承認済み公開資料を回答に利用する場合、回答内容を資料抜粋に明記された事実へ限定する指示を追加。モデルの一般知識による補完や、資料にない施設・位置・習慣等の創作を避け、根拠文に出典番号を付ける。
- 日本語品質修復にも同じ資料抜粋を渡し、修復時に出典根拠が失われないようにする。
- 既知の不自然な言い回しと、文末の連用形「あり／おり」を検出。修復後も残る場合は未完了の最終節だけを除去する。
- これはプロンプトと限定的な品質検査であり、モデルの事実誤認を完全に防ぐものではない。重要事項は出典本文との照合が必要。

## 日本語の最終安全補正（v93）

- Qwenによる修復生成の後にも、既知の不自然表現を表示直前のローカル補正で置換する。
- 未完了の連用節（「あり／おり」）が文末に残った場合、最後の未完了節だけを除去する。完結文が残らない場合は不完全な断片を表示せず、再質問を案内する。
- 既知の不自然表現が残る場合も安全な案内へ置き換える。ユーザー記憶・履歴の保存形式、暗号化、同期、バックアップは変更しない。
- ルールは既知パターンに限定され、未知の文法誤りや事実誤認を完全に検出するものではない。

## 不自然な文の安全な除外（v94）
- 「富士山登り」を含む既知の不自然な文は、語句の単純置換で新しい主張を作らず、文単位で除外する。
- これは既知パターンのみを扱う安全策で、一般的な日本語の意味解析ではない。
