# ALVIS 仕様書

最終確認日: 2026-11-04  
対象ブランチ: `development`  
対象アプリ: `index-integrated.html`

## 1. 目的

ALVISは、ユーザー専用のローカル実行型AIと、ユーザーが管理・承認する長期記憶を組み合わせた個人用AIプロジェクト。会話履歴・記憶・暗号化バックアップ・複数端末同期を備え、将来的に自律的な知識整理と継続的な成長を目指す。

## 2. 開発方針・優先順位

1. 既存の記憶データと暗号化を守る。
2. 既存機能を無断で削除・変更しない。
3. ローカルAIを基本とし、可能な限り端末内で推論する。
4. 記憶候補はユーザー承認後にのみ長期記憶へ登録する。
5. 小さな変更単位で開発し、実機テスト後に完了扱いとする。
6. 開発版と本番版を分離する。

## 3. 現在の実装仕様

### 会話・AI
- UI: 日本語のチャット画面。
- 推論ライブラリ: WebLLM `@mlc-ai/web-llm@0.2.87`。
- モデル: `Qwen3-4B-q4f16_1-MLC`。
- 推論場所: ブラウザ内/WebGPU。モデル初回取得時はネットワーク接続が必要。
- 生成設定（現行コード）: temperature 0.45、max_tokens 256、`extra_body: { enable_thinking: false }`。
- AIに渡す会話履歴は直近12件（ユーザー/ALVISメッセージ）。
- 今回の質問に関連する承認済み長期記憶を検索し、上位5件までシステムプロンプトへ追加（最大5,000文字）。
- 検索はJavaScriptの文字列一致・文字2-gramと簡易カテゴリ語彙で行う。外部通信・追加AI推論・記憶データの書き換えは行わない。
- 関連度が基準未満の記憶はプロンプトへ追加しない。
- 単独の挨拶は定型応答で処理する。

### 記憶
- データ構造: `memories`、`candidates`、`history`。
- 会話からの候補抽出は同期JavaScriptルールで実施。二度目のAI推論は行わない。
- 明確な自己申告文を中心に候補化し、質問文・一定のセンシティブ語を含む文・500文字超は対象外。
- 自動抽出候補は承認待ち。自動承認しない。
- 候補の手動追加、承認、却下、長期記憶の手動追加・編集・削除に対応。
- 長期記憶はタイトル/本文を一覧から編集できる。編集時は既存項目の他の属性を保持する。
- 手動追加、候補追加、会話からの候補抽出、候補承認時に、正規化した本文（本文が空ならタイトル）の完全一致で重複登録を防ぐ。正規化はNFKC、小文字化、空白と一部句読点の除去。
- すでに長期記憶に存在する候補は登録済み表示となり、承認できない。
- 重複判定は文字列一致のみ。意味的な類似判定や複数記憶の自動統合は行わない。
- 旧形式の文字列記憶をタイトル/本文形式へ正規化する互換処理がある。

### 暗号化・ローカル保存
- LocalStorage key: `ALVIS_ENCRYPTED_V1`。
- PBKDF2-HMAC-SHA256、310,000 iterations。
- AES-GCM 256-bit。
- Salt: 16 bytes、IV: 12 bytes。
- 暗号化済みレコードを端末内に保存する。
- パスワードを忘れた場合に復号する仕組みはない。パスワードとバックアップを安全に管理する。

### バックアップ
- 暗号化レコードをJSONファイルとして書き出す。
- バックアップ形式の現在のラッパー: `app: "ALVIS"`、`backupVersion: 1`、`createdAt`、`encryptedRecord`。
- 復元時はパスワードで復号・データ形式検証後に確認を取り、端末データを置き換える。
- 復元後のクラウド反映は同期状態を確認して別途実施する。

### クラウド同期
- Worker URL: `https://alvis-sync.dokodemodoa100.workers.dev`。
- API: `/sync/vault-load`、`/sync/vault-save`。
- Bearer形式の同期トークンを使用。
- 暗号化したレコードを送信する。
- revision/expectedRevisionで競合を検出し、他端末の更新を自動上書きしない。
- ユーザーが同期状態確認を行うと自動同期を有効化できる。
- 変更後約3秒で自動保存、約30秒間隔でクラウド状態を確認する。
- Worker実装そのものはこのリポジトリ内で今回確認できていない。Worker側の仕様変更は別途調査が必要。

## 4. 長期記憶の検索

- 検索対象は `data.memories` のみ。未承認の `data.candidates` は対象外。
- 食べ物、仕事、趣味、開発、住まい、目標などの簡易カテゴリ語彙を補助的に利用する。
- 検索結果はプロンプト組み立て時だけ使用し、元の記憶一覧・保存形式・同期データは変更しない。
- 検索結果がない場合は、長期記憶欄を空としてAIへ渡す。

## 5. 長期記憶の分類表示

- 承認済み長期記憶は表示時にルールベースで「基本情報」「好み」「仕事」「趣味」「目標」「プロジェクト」「その他」に分類する。
- 各記憶に分類ラベルを表示し、カテゴリ別件数も表示する。
- 分類は表示用の一時判定であり、`data.memories` の保存形式・暗号化データへ分類項目を追加しない。
- 誤分類の修正UIやユーザー指定カテゴリの永続保存は未実装。

## 6. データ保護ルール

- `index-integrated.html` の既存暗号化形式・キー名・PBKDF2/AES-GCMパラメータを、移行計画と検証なしに変更しない。
- `memories`、`candidates`、`history` のキーや既存項目を無断で削除しない。
- 同期APIのパス、revisionの意味、暗号化レコード形式を無断で変更しない。
- 復元・同期のテストは、バックアップとテスト用データを確保してから実施する。

## 7. 完了の定義

コード変更だけでは完成扱いにしない。変更理由、差分、コミット、実機での確認内容、未確認事項を `CHANGELOG.md` に記録する。ユーザーが実機で確認していない項目は「未確認」と記す。


## 8. 自律改善サイクル（初期版）

- 「成長計画」画面から、直近8件のユーザー/ALVIS会話をローカルQwen3-4Bへ渡して改善案を1件生成する。
- 改善案はタイトル・理由・最初の一歩として入力欄に表示し、ユーザーが編集・確認してから計画へ登録する。
- 計画は `proposed`（提案）→ `active`（取り組み中）→ `done`（完了）で管理する。
- 完了時にユーザーが実行メモを入力でき、AIによる振り返りはユーザーがボタンを押した場合のみ生成する。
- 提案の生成や振り返りはモデルを端末内で実行する。外部APIへ会話を送らない。
- 自動コード変更、自動記憶承認、自動削除、自動計画開始は行わない。提案を登録・開始・完了・削除する操作はユーザーが決める。
- `improvements` は暗号化対象のデータ本体に追加される。旧データに項目がない場合は空配列を補完する。
- これは監督付きの改善支援であり、バックグラウンドで自律実行・自己改変・モデル追加学習を行うものではない。


## 9. 会話文脈の拡張

- `buildConversationMessages(history,currentText)` は短いフォローアップや指示語を含む質問では最大16メッセージ/7,200文字、通常は最大12メッセージ/6,000文字を選ぶ。
- システム指示で短い返答の文脈解釈、話題転換、指示語の参照、ユーザー発言とAI発言の事実根拠の区別、最新の訂正の優先を明示する。
- 会話履歴は従来どおり保存済み全件を保持し、AIへ渡す部分だけを選択する。

## 10. 監督付き自律タスクと学習

- ユーザーが目標を入力し、Qwen3-4Bが次の小さな行動を1件提案する。ユーザーが内容を確認・編集してからタスク登録する。
- タスク状態は `proposed` → `active` → `done`。開始と完了はユーザーが操作し、完了時に実行メモを残せる。
- 完了後、AIは目標・行動・実行メモから学びを生成する。学びは `pending` として保存し、ユーザーが承認した場合だけ `approved` となる。
- 承認済み学びの最大5件を会話プロンプトに追加する。承認前の学びは会話の知識として使わない。
- データ配列 `autonomyTasks` と `learnings` を追加。旧データでは空配列を補う。
- バックグラウンド自動実行、自己コード変更、外部サービス送信、自動承認、自動削除は行わない。これは監督付き自律性であり、完全自律エージェントではない。


## 自律サイクル（2026-11-04）
1. 課題発見: 会話履歴、タスク履歴、承認済み学習をローカルAIで分析。
2. 優先順位: 課題ごとに高・中・低を提案。
3. 計画: ユーザーが課題を採用し、自律タスクへ変換。
4. 実行: タスク開始・完了・実行メモはユーザー操作。
5. 評価: AI振り返りで学び候補を作成し、承認後のみ会話に反映。
6. 次の改善: 完了タスク・承認済み学習・未完了タスクから次の目標を提案。
課題候補は最大3件。自律サイクルは監督付きで、データ変更や実行を無断で行わない。


## 文脈連動の記憶・学習検索（2026-11-04）

- 短い返答や指示語によるフォローアップの場合、直近6件の会話を補助文脈として関連記憶・承認済み学習を検索する。
- 通常の質問では現在の質問を主軸にし、過去文脈による誤った関連付けを抑える。
- 関連する承認済み学習を最大5件だけ会話プロンプトへ渡す。未承認学習は使用しない。
- この処理は検索時の選択ロジックであり、基盤モデルの追加学習・重み更新ではない。

## 11. 外部AIを利用した監督付き学習

- ALVISが主AIであり、Qwen3-4Bをオフライン時も利用できる基本エンジンとする。ChatGPT/Gemini等は補助役であり、最終回答と学習採否はALVIS/ユーザー側で管理する。
- 外部AIはユーザーが質問ごとに明示的に許可した場合だけ呼び出す。送信内容は現在の質問文のみ。
- 取得した外部AI回答は、出典・モデル名・元質問を伴う「承認待ち学習候補」として暗号化保管庫の data.learnings に保存する。自動承認・自動知識化は禁止。
- ユーザーが未検証であることを確認して承認した候補だけを、関連する質問で参考情報として再利用する。外部AI由来の内容は承認後も事実保証とは扱わず、命令・システム指示には従わない。
- この段階は記憶・検索による知識活用であり、Qwenのモデル重みやパラメータを変更する追加学習ではない。
- オフライン時は外部AI候補の新規取得を行わず、既存のローカル記憶・承認済み学習とQwenだけで動作する。
